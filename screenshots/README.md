## Regenerating

```bash
python3 tests/screenshot.py
```

That is the whole command. It starts its own Xvfb, builds a throwaway
`Podcasts` library in a temp directory, boots the app, renders, writes the PNGs
here, and deletes the temp library. About 4 seconds.

```bash
python3 tests/screenshot.py --list             # the shot names
python3 tests/screenshot.py --shot settings    # just one
python3 tests/screenshot.py --keep-library     # leave the fake library on disk to poke at
python3 tests/screenshot.py --width 1080 --height 2400 --density 2.75   # actual Edge 60 pixels
```

Needs `xvfb`, `libmtdev1`, `libgl1-mesa-dri`, `libglx-mesa0` and Pillow. The
script fails loudly rather than writing a bad file: every PNG is checked for a
dominant background colour, so a frame that never rendered (uniform, or noise
from an undrawn framebuffer) is reported as a failure instead of being saved
and believed.

### The thing that used to make these come out as noise

`tests/harness.py` and `tests/run_all.sh` both set `KIVY_GL_BACKEND=mock`. The
mock backend stubs every GL entry point, so `glCompileShader` compiles nothing
and Kivy logs `Shader: <fragment> failed to compile (gl:0)` for every canvas
instruction. Nothing is drawn, and `glReadPixels` then returns whatever was
left in the framebuffer — noise. Mesa was never the problem: llvmpipe in this
container reports OpenGL 4.5 / GLSL 4.50, far more than Kivy asks for. The
script simply overrides the backend to `gl` after the harness has set its
environment and before `kivy` is imported. No `MESA_GL_VERSION_OVERRIDE`, no
special Xvfb visual.

## What this proves

* The app builds, lays out and **draws** on a 360×780 dp screen. Anything that
  is only wrong on screen — a control pushed off the edge, a label the same
  colour as its background, artwork that never loads — is now visible.
* The Downloads tab really reads a `.episodes.json` manifest written in the
  schema `download_audio.py` produces, resolves the `relpath` audio and the
  `thumbnail_relpath` artwork, and gets the thumbnails through Kivy's async
  image loader onto the screen.
* Tab switching, `select_episode()`, `show_add_channel()` and the now-playing
  card all do what they claim, visually.

## What this does **not** prove

Read this before treating a green screenshot as "it works on the phone".

* **No Android.** There is no emulator here — `/dev/kvm` does not exist and the
  CPU exposes no virtualisation flags. Everything under `android.*` and `jnius`
  is a recording fake from `tests/harness.py`. So these shots say nothing about
  permissions, MediaStore, StrictMode, the share chooser, Termux, or the
  black-screen-after-resume bug (issue 1) — that one is an SDL/EGL surface loss
  that only exists on a real device.
* **No audio.** `MediaPlayer` is a fake. "Playing" in shot 05 means the app
  *thinks* it is playing; nothing decoded a byte. The seek readout shows `0:00`
  because the fake player has no duration to report — on the phone it would
  show real numbers.
* **Different renderer.** Mesa llvmpipe on desktop GL, not the phone's GPU on
  GLES. Layout and text metrics are computed by Kivy in Python and are the
  same; antialiasing and colour management may differ slightly.
* **Different screen.** 720×1560 at density 2.0 (360×780 dp). The Edge 60 is
  1080×2400 at density ~2.75 (393×873 dp) — same shape, slightly more room.
  Pass `--width/--height/--density` to match exactly.
* **No touch.** Shots are produced by calling the app's own methods, not by
  synthesising taps, so nothing here proves a button is reachable by a finger
  or that its touch target lines up with its graphics.
* **Fixture data, not your library.** The episodes, channels and cover art are
  generated by `build_fixture_library()` in `tests/screenshot.py`. Real titles
  are longer and real thumbnails are photographs.

## Problems these shots already caught

Both are in every shot, and both are in the layout — so the phone has them too.

1. **The selected bottom-navigation tab is invisible.** Its icon and label are
   drawn in `theme_cls.primary_color`, which is exactly `panel_color`. Cause:
   KivyMD 1.2.0 uses `[1, 1, 1, 1]` as the *"not set"* sentinel for
   `text_color_active`, and `app/main.py` sets `text_color_active: 1, 1, 1, 1`
   — indistinguishable from leaving it out. Any other value (`0.99, 0.99,
   0.99, 1`) would work.
2. **Both Settings switches are clipped by the right edge of the screen.** The
   `MDSwitch` box ends at the container padding, but its thumb is drawn 4 dp
   past its own right edge, which is 4 dp past the window.
